How attachment opening works

Clicking an attachment in the list opens a new tab that loads the file from the local database (never the network) and decides how to show it:

File typeWhat happens
Images (PNG, JPG, GIF…)Shown inline, scaled to fit, with a Download button.
PDFRendered by Chrome's built-in PDF viewer inside the tab, plus a Download button.
Everything elseFilename + size + a Download button (no preview).

A design decision worth noting: we originally planned to show PDFs inside the locked sandbox, but a fully locked sandbox blocks the PDF plugin — it would show nothing. Since attachments are your own team's files (trusted, unlike email body HTML), we show the PDF in a normal frame on the extension's own page, which lets Chrome's native viewer work. The file is loaded as a temporary in-memory link that's released when you close the tab.

Polish added

  • Loading spinner while a file is parsed and saved.
  • "Open another file" button in the reader tab, so you don't have to go back to the icon.
  • Friendly error messages for: wrong file type, file too big (50 MB cap), corrupt/unparseable email, an attachment or email that's no longer available, and emails with no readable body.
